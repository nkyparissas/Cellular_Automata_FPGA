# Lenia Rule Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Lenia as a fourth rule plug-in (`RULE_LENIA`) with per-distance-class programmable weights, a double-buffered host-driven growth table, a bit-exact golden model, host support and 1920x1080 defaults, without changing any existing rule or result.

**Architecture:** The model (`model/ca_model/lenia.py`) is the single source of the class map, the quantised weights and the growth table. In RTL, `ca_rule_lenia` (eclk) pre-adds each distance class, multiplies by a local weight register of a shift chain, sums, shifts, reads the active table bank and saturates; `ca_lenia_ctrl` (aclk and eclk) owns the kernel FIFO, the bank and SH registers, the commit and `GROWTH_GEN`, and holds the pass controller while a kernel load is pending (a growth commit never holds a pass). `ca_regs` decodes 16 address bits and exposes the new registers only in Lenia cores.

**Tech Stack:** SystemVerilog (Verilator 5, cocotb 2.1-dev, yosys-slang), Python 3.11 (numpy, pillow), pulp axi / common_cells.

**Spec:** `docs/superpowers/specs/2026-10-31-lenia-rule-design.md` (base: `docs/superpowers/specs/2026-10-24-ca-sv-framework-design.md`).

## Global Constraints

- Engine clock 200 MHz: every adder level and shifter stage is registered, multipliers use input, product and output registers, the table output is registered, window cells reach their class pre-adders through at least one register stage, and weight registers sit next to their multipliers; function must not rely on multicycle or false-path constraints.
- Incremental: existing rules, configurations (`configs/*.json`), register offsets and results are unchanged; all six existing configurations still build and run bit-exactly.
- 1920x1080 is the default everywhere; tests pass small sizes explicitly; running any configuration at 1920x1080 needs only its JSON file.
- Lenia defaults `CELL_W = 16`, `WEIGHT_W = 6`, `LUT_IDX_W = 12`; 8-bit cells stay supported.
- Synchronous resets only; reset control and valid state, never data (weights, table contents, SH values).
- RESET_STATE does not touch kernels or tables.
- RTL simulations run at most 200 generations (`tools/run_rtl_experiment.py` MAX_GENS); long horizons use the model.
- No new Python dependencies and no package installs: numpy (including `numpy.fft`) and pillow only.
- Downloaded files are untrusted: each goes into its own new empty directory, is parsed as data (JSON, `ast`), never executed, and every script reading it runs with `python3 -I` from another directory.
- Every commit needs the user's approval (see the handoff); never push.
- Documentation follows the user's writing style (formal, connectives, no em dashes).

## Plan decisions (not fixed by the spec; the user checks these)

1. `WEIGHT_W <= 15` instead of 18, because `LENIA_CFG[11:8]` holds `WEIGHT_W` in 4 bits.
2. Lenia cores require `CELL_W` of 8 or 16 (the entry width `CW + 1` must fit `LENIA_CFG[20:16]`).
3. New parameter `GROWTH_SH_DEFAULT` (power-up SH of both banks), generated by `tools/gen_cfg.py` with the table.
4. `KERNEL_PENDING` compares a count of accepted words (aclk) with a gray-coded count of words already shifted into the chain (eclk to aclk, `ca_gray_xfer`), so it clears only after the last shift.
5. (Agreed with the user on 2026-10-31.) A growth commit never holds a pass: the bank swaps in any cycle in which no pass is running (the controller's `active` flag, new output `active_o`; BUSY stays high while fast-forward passes remain, so it is not used). The controller decides a pass start in one cycle and `ca_params_cdc` captures the bank in the next, so a swap in the same cycle as a start decision still reaches that pass; every pass uses one table and `GROWTH_GEN` marks the switch. Only a pending kernel load holds pass starts, and its pending flag clears without the controller, so no wait cycle exists.
6. A hardware reset clears the pending bits and `GROWTH_GEN`, and keeps the active bank, both SH values, the table and the weights.
7. `GROWTH_TABLE` writes with an index of `2^LB` or more are ignored; a second `GROWTH_COMMIT` while one is pending is ignored.
8. Rule latency: register stage 1, pre-add `tree_lat(max cells per class)`, multiply 3, sum `tree_lat(C)`, index 3 (shift by `SH[5:3]*8`, shift by `SH[2:0]`, saturate), table 2 (RAM register, output register), update 1. Deeper stages are allowed if Vivado later needs them.
9. `viridis` uses matplotlib's 256-entry viridis data (CC0); palettes index the top `min(CW, 8)` bits.
10. Patterns imported: Orbium, Hydrogeminium, Smooth wanderer (the tutorial's single-kernel creatures).
11. CLI keys: `[` and `]` lower and raise mu by 0.001, `{` and `}` lower and raise sigma by 0.0005.

## Review Focus

1. A growth commit while fast-forward passes remain (`GENS_PER_FRAME > 1`) must swap at the next boundary and never deadlock. Tests: Task 7 `cocotb_growth_bank_and_commit` (BUSY high, `active` low), Task 8 `test_lenia_core_commit_with_fast_forward`.
2. `GROWTH_TABLE` writes beyond the table (index `>= 2^LB` inside the 0x8000 window) must be ignored, never aliased into a bank. Test: Task 7 `cocotb_growth_bank_and_commit`.
3. Cores built with another rule: offsets 0x60 to 0x70 and the table window read 0 and ignore writes, STATUS bits 3 to 5 read 0, and with 16-bit decoding 0x0104 no longer aliases CTRL while 0x10004 does. Test: Task 7 `tb_ctrl` cases `decode16` and `lenia_absent`.
4. A display board requests passes continuously: a commit must still take effect between two passes, `set_growth` must return, and the replay from `GROWTH_GEN` must match. Tests: Task 8 `test_lenia_core_growth_commit_midrun[sink]`, Task 10 `test_set_growth_display_paced`.
5. Bad inputs fail loudly: a `unit16` seed that is not a 16-bit greyscale PNG, a Lenia configuration with `R > (nbh - 1) / 2`, `R < 1`, a cell width other than 8 or 16, or missing or unknown parameters. Tests: Task 2 `test_config_lenia_validation`, Task 5 `test_unit16_rejects_8bit_png`.
