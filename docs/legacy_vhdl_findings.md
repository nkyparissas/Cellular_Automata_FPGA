# Findings in the legacy VHDL design

Source: the legacy repository `Cellular_Automata_FPGA` (commit 57eca66), reviewed by reading the code on 2026-10-24. Line numbers refer to that commit. The status column is updated by the GHDL tests of Task 23 (`tests/legacy/`).

| # | Location | Finding | Impact | Status |
|---|---|---|---|---|
| 1 | `GRAPHICS_FEEDER.vhd:116-125`, `WRITE_BACK.vhd:99-108`, `TOP LEVEL.vhd:621-625` | The graphics feeder and the write-back each keep their own speed counter and `SELECTED_FRAME` bit and evaluate them at different moments of the frame (an estimated 150 µs apart). Pause is restricted to a safe band of rows, but the Up/Down buttons are not, and they are neither synchronised nor debounced. | A press inside that window can leave reader and writer on the same buffer permanently, so generations are computed from partially overwritten data. | unconfirmed |
| 2 | `MEMORY_INITIALIZER.vhd:126-133` | If `APP_WDF_RDY` drops while in `WRITING_3`, the FSM returns to `WRITING_2` with `APP_WDF_WREN` still asserted and pushes a third data beat. | The MIG write-data FIFO becomes misaligned with the commands; later writes land with the wrong data. | unconfirmed |
| 3 | `WRITE_BACK.vhd:94, 133, 167-172` | `COMMANDS_SENT_COUNTER`/`ADDRESS_COLUMN` advance on `APP_EN and APP_RDY` without checking `MEM_ACCESS_GRANTED`, and the re-presentation term of `APP_WDF_WREN` is not gated by the grant, whereas `BURSTS_WRITTEN_COUNTER` is. | When the arbiter switches while the MIG is stalled, a write command may be lost or a data beat duplicated. Probably rare. | unconfirmed |
| 4 | `GRID_LINES_TOROIDAL_BUFFER.vhd:189-194, 241` (same in `GRID_LINES_BUFFER.vhd`) | The line-buffer RAM write enable follows `APP_RD_DATA_VALID` regardless of the grant, while the write address advances only when granted. | Correctness relies on the display's request window covering the whole read latency. | unconfirmed |
| 5 | `TOP LEVEL.vhd:477-511` | The write-back FIFO full flag is unused and the engine cannot be stalled. | Silent overflow if write-back is starved. | unconfirmed |
| 6 | `GHM/CA_ENGINE.vhd:741` | The state wraps at `CURRENT_CELL+1 >= N-1`, so with `N=16` only states 0..14 occur (the legacy `result.txt` contains exactly 0..14). Generic `E` is unused. | 15 instead of 16 states. Reproduced in the new design with `STATES=15`. | confirmed by data |
| 7 | `Hodgepodge n19 Exploration Mode/TOP LEVEL.vhd:26` | Sets `NEIGHBORHOOD_SIZE=29` while its engine is hand-built for 19 (centre `(9,9)`, adder-tree widths). | Inconsistent build; the 19x19 result was produced by the n29 exploration engine instead. | unconfirmed |
| 8 | `FHD_CTRL.vhd:89, 105-106` | Counters run `0..HMAX` and `0..VMAX` inclusive: 2201 x 1126 instead of 2200 x 1125. | 59.92 Hz instead of 60 Hz; harmless for monitors. | unconfirmed |
| 9 | `MEMORY_INITIALIZER.vhd:155` | `ADDRESS_ROW` is incremented to `GRID_Y`, outside its declared range. | Fatal range error in simulation, benign in synthesis. | unconfirmed |
| 10 | `SYNCHRONIZER.vhd`, `GRID_LINES_TOROIDAL_BUFFER.vhd:252, 262` | Multi-bit counters are sampled on both edges of `CONTROL`; back-to-back `SYNC_CONTROL` pulses can sample them while they change. | Transient wrong value seen by the read FSM. | unconfirmed |
| 11 | `sw/*/uart_rx.c:139` | Reads `(H-n)*W` bytes instead of `(H-(n-1))*W` and stores rows from 0. | Non-toroidal dumps are shifted up by `(n-1)/2` rows and lose their last computed row. | confirmed by data (29 zero rows in the 19x19 result) |
| 13 | `GRID_LINES_TOROIDAL_BUFFER.vhd:82, 366` | `LINES_BEING_DRAINED` is declared `INTEGER RANGE 0 TO 2N-1` but the halo indices are incremented past `2N-1` in `WRAP_AROUND_NEIGHBORHOOD`. | Fatal range error in simulation. Synthesis builds a 6-bit register, so the value fits; co-simulation with that range shows the out-of-range values are never used to select a line. | confirmed in simulation (Task 22) |
| 14 | `GRID_LINES_TOROIDAL_BUFFER.vhd:80, 138, 149, 412` (same in `GRID_LINES_BUFFER.vhd`) | `LINE_DATA(0, I)` is driven by the BRAM instances while the READ process assigns `LINE_DATA(J, I)` through loop indices, which by VHDL's longest-static-prefix rule gives that process a driver for the whole signal. | In simulation every '1' bit of the BRAM outputs resolves to 'X', so the legacy buffer cannot be simulated as written. Synthesis is unaffected. | confirmed in simulation (Task 22) |
| 12 | throughout | `GRID_X=1920` in IP depths and address widths, 128-bit burst, frame select fixed at address bit 20, hand-coded centre index and adder trees, valid delays tied to the 34-cycle `DIVIDER` latency. | Limits generality; addressed by the new design's parameters. | by design |

## Co-simulation result

With findings 13 and 14 patched in a build copy (6-bit index range; BRAM outputs on a separate signal, same timing), the legacy toroidal buffer with the Hodgepodge n29, GHM (square neighbourhood) and Artificial Physics engines reproduces the golden model exactly for one generation of random 64x64 toroidal grids (`tests/legacy/test_legacy_core.py`, GHDL, behavioural models of the line-buffer BRAM and the 34-cycle divider). The golden model, and therefore the new RTL that matches it, implements the legacy rule semantics.

Additional observation: the 2023 orientation fix (commit 8da4942) transposed and mirrored the window without transposing the asymmetric Artificial Physics weight mask, so the post-fix VHDL implements a different neighbourhood from the one that produced the 2019 `result.txt`. The new design uses the post-fix (row, column) convention everywhere, as decided.
